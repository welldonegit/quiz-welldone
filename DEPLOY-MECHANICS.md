# Как работает деплой квиза — простыми словами

Этот файл объясняет **механику**: что где лежит, кто что запускает, почему
`npm install` всё починил, и как связаны твой компьютер → GitHub → сервер HostPro.
Без этого можно жить, но с этим ты понимаешь, что делаешь.

---

## 1. Картина целиком (за 30 секунд)

Когда человек открывает `https://quiz.well-done.com.ua`, происходит цепочка:

```
Браузер
  │  1. "какой IP у quiz.well-done.com.ua?"
  ▼
DNS  ──► 185.156.42.99   (это IP сервера HostPro)
  │  2. запрос на этот IP по HTTPS
  ▼
Сервер HostPro
  ├─ LiteSpeed (веб-сервер, "вахтёр" на входе)
  │     • держит SSL (https-замок)
  │     • решает, кому отдать запрос
  ▼
Твоё Node-приложение (процесс, запущенный из app.cjs)
  • отдаёт страницу квиза (HTML, CSS, JS)
  • обрабатывает /api/lead (приём заявок)
```

Ключевая мысль: **твой сайт — это не папка с файлами, которые просто лежат и
отдаются. Это запущенная программа (Node-процесс), которая сама решает, что
ответить на каждый запрос.** Отсюда все отличия от обычного PHP/статик-хостинга.

## 2. Три участника

| Кто | Где живёт | Его роль |
|-----|-----------|----------|
| **Твой компьютер** | локально | тут ты пишешь код и делаешь `git push` |
| **GitHub** | github.com | «склад истины» — хранит код, промежуточное звено |
| **Сервер HostPro** | 185.156.42.99 | тут код реально запускается и отвечает людям |

Код течёт в одну сторону: **компьютер → GitHub → сервер**.
Сервер сам ничего не придумывает — он забирает (`pull`) то, что ты залил на GitHub.

## 3. Директории на сервере — что где лежит

У тебя на HostPro домашняя папка пользователя: `/home/owpvmvnu/`.
Внутри важны две разные папки (и это норма, что они разные):

```
/home/owpvmvnu/
│
├── repositories/quiz-welldone/     ← ВОТ ТУТ ЖИВЁТ ПРИЛОЖЕНИЕ
│   ├── app.cjs                      • файл, с которого стартует Node
│   ├── server/                      • бэкенд (Express): приём заявок, Telegram
│   ├── src/                         • фронтенд квиза (JS-модули + CSS)
│   ├── shared/                      • общий код фронта и бэка
│   ├── assets/                      • картинки, лого, шрифты
│   ├── index.html                   • главная страница
│   ├── package.json                 • СПИСОК зависимостей (что нужно поставить)
│   ├── node_modules/                • САМИ зависимости (появились после npm install)
│   └── data/leads.jsonl             • сюда пишутся заявки (создаётся на сервере)
│
└── quiz.well-done.com.ua/           ← document root поддомена (почти пустой)
```

**Почему две папки, и почему document root пустой?**
В классическом хостинге веб-сервер отдаёт файлы прямо из document root
(`quiz.well-done.com.ua/`). Но у нас **Node-приложение**, и файлы отдаёт не
веб-сервер, а твоя программа — из папки `repositories/quiz-welldone/`.
Поэтому document root остаётся пустым, а вся жизнь — в папке с репозиторием.

Эта папка с репозиторием называется **Application Root** (корень приложения).
Именно её ты указал в настройках Node-приложения. Здесь совпадают три вещи:

```
Repository Path   = repositories/quiz-welldone   (куда git клонирует код)
Application Root   = repositories/quiz-welldone   (откуда Node запускается)
```

Они должны быть одинаковыми — тогда «куда приехал код» = «что запускает Node».

## 4. Что такое «Node-приложение» в cPanel

Когда ты в cPanel нажал **Setup Node.js App → Create**, хостинг сделал вот что:

1. Создал для тебя **изолированное окружение Node** (отдельная «песочница» с
   нужной версией Node 20 — чтобы твои пакеты не мешали другим сайтам на сервере).
2. Запомнил: **стартовый файл = `app.cjs`**, **корень = `repositories/quiz-welldone`**,
   **режим = production**, плюс твои переменные окружения (`NODE_ENV`, `TRUST_PROXY`…).
3. Настроил LiteSpeed так, чтобы запросы на `quiz.well-done.com.ua` шли в это приложение.

Дальше, когда приложение стартует, сервер по сути выполняет:

```
node app.cjs
```

а `app.cjs` запускает основной сервер (`server/index.js`), который начинает
«слушать» запросы.

**Про PORT.** Обычная Node-программа слушает какой-то порт (например 3001).
Но на хостинге много приложений — порт не фиксированный, его выдаёт сам хостинг
через переменную `PORT`. Поэтому в коде мы пишем «слушай тот порт, что дал
хостинг» (`process.env.PORT`), а сами порт не задаём. LiteSpeed знает этот порт
и перенаправляет туда запросы.

## 5. Почему `npm install` всё починил — самое важное для понимания

Твоё приложение использует чужие готовые библиотеки: `express` (веб-сервер),
`helmet` (безопасность), `zod` (проверка данных) и др. Это **зависимости**.

Тут есть хитрость, которая всех путает:

- В Git (и на GitHub) лежит только **список** зависимостей — файл `package.json`.
  Это как список покупок: «нужны express, helmet, zod…».
- Сами библиотеки (папка `node_modules/`, часто сотни мегабайт) **в Git НЕ хранятся**
  — их намеренно исключают (`.gitignore`). Таскать их через git бессмысленно.

Поэтому после `git clone` на сервере был код, но **не было самих библиотек**.
Node стартовал, в первой же строке натыкался на `import express` → «не найдено» →
падал → LiteSpeed отдавал **503** (приложение не работает).

**`npm install` прочитал `package.json` и скачал все библиотеки в `node_modules/`**
прямо на сервере. После этого `import express` стал находиться, Node поднялся —
и сайт заработал.

Аналогия: `git` привёз тебе **рецепт и чертежи** (твой код + список продуктов),
а `npm install` **сходил в магазин за продуктами** (библиотеки) уже на месте.

Отсюда правило:
> `npm install` нужен **только при первом деплое** и **когда ты добавил/обновил
> зависимость** (изменился `package.json`). В обычных правках кода он не нужен —
> `node_modules` уже лежит на сервере и никуда не девается между деплоями.

## 6. Почему НЕ нужен `npm run build`

У многих проектов есть шаг «сборки» (build): инструмент вроде Vite берёт исходники
и превращает их в сжатый, оптимизированный `dist/`. Это оптимизация, не обязанность.

Наш квиз написан на **нативных ES-модулях** (обычный JS, который браузер понимает
сам) и **обычном CSS**. Поэтому мы настроили Node так, чтобы он отдавал **исходники
напрямую** из `src/` и `shared/`. Собирать нечего → `npm run build` не нужен.

Твой цикл получается максимально простой: **изменил → push → pull → restart**.
(Если когда-нибудь захочешь сжатую версию — можно сделать `npm run build` и залить
`dist/`, сервер сам начнёт отдавать его. Но это необязательно.)

## 7. Как связаны Git и сервер (цикл обновления)

```
┌─ ТВОЙ КОМПЬЮТЕР ─┐        ┌─ GitHub ─┐        ┌─ СЕРВЕР HostPro ─────────┐
│                  │  push  │          │  pull  │                          │
│  правишь код  ───┼───────►│  хранит  │◄───────┤  cPanel Git: "Pull"      │
│                  │        │   код    │        │  обновляет файлы в        │
│                  │        │          │        │  repositories/quiz-welldone│
└──────────────────┘        └──────────┘        │                          │
                                                 │  затем "Restart" —       │
                                                 │  Node перезапускается    │
                                                 │  с новым кодом           │
                                                 └──────────────────────────┘
```

Пошагово при обновлении:

1. **Локально:** меняешь код → `git add` → `git commit` → `git push`.
   Код уехал на GitHub.
2. **В cPanel → Git Version Control:** жмёшь **Pull** (или `git pull` по SSH).
   Сервер забирает свежий код с GitHub в папку приложения.
3. **В cPanel → Setup Node.js App:** жмёшь **Restart**.
   Старый Node-процесс гасится, запускается новый — уже с новым кодом.

**Почему нужен Restart?** Node загружает код в память один раз при старте и держит
его там. Пока процесс живёт, он работает со «старой» версией. Файлы на диске
обновились (после pull), но запущенная программа об этом не знает — нужен
перезапуск, чтобы она перечитала код. (Правки в `data/` — заявки — перезапуска не
требуют, это просто файл с данными, а не код.)

## 8. DNS и SSL — в двух словах

- **DNS** — это «телефонная книга интернета». Запись `A` говорит: «имя
  `quiz.well-done.com.ua` → IP `185.156.42.99`». Без неё браузер не знает, на какой
  сервер стучаться. Мы завели одну A-запись, и этого достаточно.
- **SSL (https-замок)** — сертификат, которым сервер доказывает, что он
  действительно `quiz.well-done.com.ua`, и шифрует трафик. HostPro выдал его
  бесплатно через AutoSSL/Let's Encrypt. Выпуск требует, чтобы DNS уже работал
  (центр сертификации проверяет домен) — поэтому порядок был: сначала DNS, потом SSL.
- Наше приложение «за» LiteSpeed, который снимает SSL сам. Чтобы Node правильно
  понимал, что соединение защищённое и видел реальный IP посетителя, мы выставили
  переменную `TRUST_PROXY=1`. Это всё, что нужно было со стороны кода.

## 9. Что происходит при конкретном запросе (для полноты картины)

**Открытие страницы квиза** (`GET /`):
```
браузер → LiteSpeed (снимает https) → Node → отдаёт index.html
затем браузер догружает /src/wd-quiz.js, /src/wd-quiz.css, /assets/... — тоже через Node
```

**Отправка заявки** (`POST /api/lead`):
```
браузер → LiteSpeed → Node → server/routes/lead.js:
  1. проверяет honeypot и что заполняли не слишком быстро (анти-бот)
  2. проверяет данные (zod)
  3. пишет заявку в data/leads.jsonl
  4. в фоне шлёт в Telegram (когда настроишь токен)
  5. отвечает браузеру {ok:true}
```

## 10. Шпаргалка (держать под рукой)

**Обычное обновление:**
```
локально:  git add -A && git commit -m "что сделал" && git push
cPanel Git Version Control:  Pull
cPanel Setup Node.js App:    Restart
```

**Когда что делать:**
| Ситуация | Действия |
|----------|----------|
| Поправил код / тексты / стили | push → Pull → Restart |
| Добавил npm-зависимость (`package.json`) | push → Pull → **Run NPM Install** → Restart |
| Приложение отдаёт 503 | смотри лог приложения → чаще всего забыл npm install или Restart |
| Нужны переменные (Telegram и пр.) | Setup Node.js App → Add Variable → Restart |

**Ключевые пути:**
```
Application Root / Repository Path:  /home/owpvmvnu/repositories/quiz-welldone
Стартовый файл:                      app.cjs
Заявки:                              …/repositories/quiz-welldone/data/leads.jsonl
Сайт:                                https://quiz.well-done.com.ua
Проверка жив ли бэкенд:              https://quiz.well-done.com.ua/api/health → {"ok":true}
```

**Три вещи, которые должны совпадать:** Repository Path = Application Root =
папка, где реально лежит `package.json`. Если они разъедутся — Node запустит не
ту папку, и будет 503.
